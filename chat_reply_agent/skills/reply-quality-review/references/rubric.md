# 评估标尺 v3

## 五档的含义

- 1：明显错误或有风险，例如把拒绝改成答应、编出承诺、直接断言对方心理。
- 2：有实质问题，需要改才能发送，例如接错话、忽略明确限制、关系明显越界。
- 3：基本能接，但能指出具体不足，例如没回应关键处、语气有点敷衍、关心太泛。
- 4：贴合当前对话、顺口、分寸合适，只有小的改进空间。
- 5：有具体证据说明比“能用”更贴切：兼顾关键限制、对方话里的余地和本人的习惯。不是“没违规”就给 5。
- null：证据不足。个人风格样本缺失不等于风格不合，也不能给默认满分。

## 维度

| 字段 | 重点看什么 | 不能偷换成什么 |
| --- | --- | --- |
| naturalness | 读起来像顺手发的微信；允许省略和停顿；语气词是否合场合 | 短就好，长就差；主谓宾完整就必然像 AI |
| relevance | 接住对方最后一句，保留用户意图和时间、条件、承诺边界 | 提到同一个话题就算接得好 |
| relation_fit | 称呼、亲密程度、主动程度符合已知关系；不讨好、不施压 | 甜一点或客气一点总是更好 |
| scenario_fit | 照顾具体处境和可能的情绪；事实、天气、时间有依据 | 自信地推断对方生气；把预报当实测 |
| style_fit | 有本人原句或可靠风格记录支持长度、语气、停顿等判断 | 只因口语化就断言“很像本人” |

每项 evidence 说明依据和不足；null 的 evidence 说明缺失信息。
issues 写需要调整的具体问题；hard_issues 单列改变立场、编造事实或承诺、越界施压等明确缺陷。
只读评测中 critical_unknowns 只写会改变这条回复是否合适的关键未知，并说明缺少什么、为什么影响选择。例如“没有目的地，无法判断这里说的天气是否适用”。
advisories 写不阻止使用的普通提醒，例如“无法保证对方反应”“没有本人风格样本”。不能因为不了解全部背景或无法读心就把所有回复判为信息不足。
情绪有歧义时，判断候选是否仍能稳妥回应：不依赖特定情绪的中性回复可以通过；直接认定生气、背叛等则按具体缺陷处理。不要把对方明确说的“我很烦”也当成无法判断。
定向编辑旧协议中的 uncertainties 仍只放关键未知，遵循当次输出结构，不混用字段。
没有本人风格样本时（has_style_evidence=false）style_fit=null，在 evidence 说明即可，不必因此否定其他四项。“用户不喜欢长句”等负面反馈可用于避雷，但本身不是本人风格样本。

## 对照例子（用于理解标准，不是回复模板）

### 对方收回邀请

背景：本人已有安排，表示六点半回来后能暂时补位、人齐就走。对方说“算了算了你去玩”。

- “你别生气，我明天一定陪你”：把猜测当事实，又新增承诺。relevance / scenario_fit 有明确缺陷，hard_issues 必须指出。
- “好啦，那我先去了，你们玩开心”：能收尾，但“好啦”在亲近、轻松语境里可能自然，在失落语境里可能像敷衍；不要一律判好或判坏。不能仅凭最后一句认定对方在生气。
- “行，那我先去了，要是缺人再说”：不一定是硬承诺，但重新打开对方已经收回的补位话题，也省掉了原有时间限制，需说明这个风险。
- “那你们玩得开心，我先去了”：与上一句“好啦，那我先去了，你们玩开心”几乎是同一种接话作用。字序不同不算新的选择。
- 更短的“行，那你们玩”也不是标准答案；要结合双方平时的说话习惯，不能强行加安慰或道歉。

### 明确表达感受

对方：“今天被领导说了一通，烦死了。”
- “积极沟通，共同解决问题”：像建议报告，也没有接住当下抱怨。
- “啊，怎么说你的”：有具体接话动作，但如果对方刚说“不想再讲”，继续追问就不合适。
- “你一定很崩溃”：把已知的烦扩大成没有证据的情绪。关心的措辞不自动获得高分。

### 事实与天气

对方问“明天出门要不要带伞”。只有今晚预报时，不能写“明天肯定不下雨”；缺少地点时不能猜城市。缺失湿度、空气质量不等于零。保留日期、时段和预报不确定性。

### 关系和风格

同事问“材料今天能给吗”，用户明确还没做完。不能为了热情写“放心，马上给你”；“今天还差一点，明早给你行吗”也需要用户确实能明早交付，不能凭空补截止时间。
没有本人的原句时，可以判断句子通顺口语化，但 style_fit 必须留空。

## 完整性与立场

把一个候选的多段文字作为完整回复评估，不能按气泡单独打分。先看事实边界、用户立场和必要回应是否保留，再看口吻。
字数多、标点多、主谓宾完整或出现“我希望”“我尊重”，都不能单独作为AI腔的证据；字少、礼貌、没有攻击性也不自动等于好回复。
对方有情绪不证明用户有错。无依据地代用户认错、撤回合理疑问、只安抚对方却漏答用户关心的事，应在 relevance / scenario_fit 指出具体缺陷。
用户确有责任时，具体承担责任不是软弱，不为鼓励坚定而一律反对道歉。坚定表达不满也不是攻击；需要依据区分具体要求与威胁。
系统提示中断不能改写为占线或确定有人来电；尊重不发截图不等于没有沟通问题。未知动机不得当事实，缺乏证据不妨碍表达已确认的不满。
候选仅说“我不问了”“别生气”而漏掉本轮核心问题时，不因顺口或较短给高分；必要解释也不能因为超过旧字数偏好被改成这种收场。

## 候选组差异

只读评测的 group_review.batch_id 使用输入给定的整组编号，不复制候选全文。
定向编辑模式若要求 evaluated_texts，则逐条按顺序返回输入候选；按当次输出结构执行，不能混用两种协议。
distinct=true 表示有实质的接话作用差异，false 表示至少两条只换词换序，null 表示证据不足。
reason 要指出具体候选及其作用；不因“温和说明”“安抚确认”等标签不同就认为有差异。
复杂问题的候选可以共用必要事实和核心立场，通过表达直接程度、重点或组织方式提供选择；不能为了差异强迫一条道歉、一条反击、一条放弃问题。仅换词换序仍不算实质差异。
只对原始候选组下结论。某条被修改后，旧的组评估不能沿用到新组合。
