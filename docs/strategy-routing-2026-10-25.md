# 完整表达与按需策略（2026-10-25）

本轮先修表达约束和评分偏差，再接入可选策略读取，最后做离线回归。保留 FastAPI、SQLite、现有生成模型及独立评审，不改个人记忆、真实 `.env`、依赖或数据库结构。

## 1. 不再把口语化等同于短句

- 默认长度改为“按内容决定”。日常接话可一句，复杂解释和冲突可以写成一套 2-4 段短消息。
- “稍完整”的参考预算从 8-36 字调整为 20-180 字；“短句”为 4-50 字，“很短”仍为 2-12 字。这些是偏好，不是裁切规则；现有生成结构仍有每条 600 字的保护上限。
- 每个候选仍是一套完整回复。空行保存在原有 `ReplyCandidate.text` 中，不把四句话拆成四个候选，无需迁移数据库。
- 页面输入框随内容展开，长内容可滚动、可手动调整大小。初次显示、解除高风险等待、主动使用修订稿及手动编辑都处理多段显示；评审轮询不改正文、不抢光标。
- 公共约束要求保留必要事实、用户立场和双方已经表达的感受。关心不意味着默认认错，坚定也不意味着反击；有具体责任时仍应承担对应责任。旧的风格偏好不覆盖本轮需求。

## 2. 基础约束与可选策略分开

基础约束始终生效，见 `chat_reply_agent/services/reply_policy.py`。关系名称、阶段和边界仍进入上下文；场景只提供分类名称和描述，不把完整关系手册、全部场景策略和例句一起塞入生成提示。

新增本地只读工具 `load_reply_skills`。首轮模型只看策略 ID 和适用描述，需要具体方法时才读取正文；模型也可以直接生成，不调用任何策略。

| 策略 | 用途 | 不代表什么 |
| --- | --- | --- |
| clarify-facts | 澄清可见事实与推测 | 不把提示当作动机或行为证据 |
| assert-position | 表达具体不满、拒绝和要求 | 不代用户决定强硬立场 |
| take-responsibility | 对明确行为具体负责 | 冲突不自动触发道歉 |
| pause-conflict | 有需要时暂停升级并保留问题 | 不默认放弃沟通或承诺明天再聊 |
| respond-to-feelings | 回应明确表达的感受 | 不读心，不只安抚而漏答问题 |

文件位于 `chat_reply_agent/skills/reply-strategies/<id>/SKILL.md`，使用 `name`、`description` 和 `metadata.version`，正文包含适用边界、表达方法、日常例子及检查点。采用先目录、后正文的加载方式，参照 [Agent Skills 格式与渐进式加载规范](https://agentskills.io/specification)。这是项目内的轻量读取实现，不是完整 Claude Skills 运行时，也不会执行 Skill 脚本。

本工具不需要新的 MCP 服务，不调用另一个模型，不读取任意路径，不执行命令、不联网、不写数据库。现有天气工具仍走 MCP。未知 ID、重复 ID、多余参数、越界路径、无效/不可读文件均返回失败信息；模型应回到基础约束，不假装读取成功。

## 3. 次数、耗时和关闭方式

- 一次生成调用最多读取一次策略，可在该次请求中选择最多两个 ID；无效参数也消耗这次机会。
- 与天气工具共用最多三轮文本模型请求；天气最多尝试两次。第三轮强制结束工具选择；模型仍继续发工具调用则报错，不无限追加调用。
- 策略读取本身不花模型费用，但模型选择工具后再生成通常多一个请求轮次。减少首轮提示不等于保证提速，总延迟和效果要实测。
- 评审和记忆角色不暴露策略工具；定向修订使用公共约束及评审依据，不另开策略循环。
- 折叠的生成耗时详情显示已返回的文本模型请求次数、读取的策略 ID/版本和读取耗时。日志还记录供应商实际返回的 token 用量；不记录聊天原文、策略正文或密钥。
- 这些上限针对单次生成/重生成的工具循环，不含独立后台评审、修订和复评。

开关为 `REPLY_SKILLS_ENABLED=true`，默认开启。兼容接口不支持工具调用或需要只对照基础约束时，可设为 `false` 后重启；关闭后仍保留新的表达规则，不恢复旧的全量模板注入。天气开关独立。如同时不支持天气工具，需要一并处理 `WEATHER_TOOL_ENABLED`。本轮未替用户改写配置文件。

## 4. 评审不会再把长句自动判成 AI 腔

评估标尺更新为 `reply-quality-v3`：

- 删除本地按字数、标点数量和普通表达词直接扣自然度的规则。非空文本的本地自然度是 `null`，不是默认 5/5。
- 长度超过明确偏好时可以给普通提醒，但不会据此覆盖模型的自然度判断或强制修订。
- 评审按整个候选检查：是否漏答核心问题、擅自认错、撤回合理要求、推断动机、编造事实或承诺。不会仅因坚定就判好，也不会因为礼貌就放行。
- 候选应保持核心立场，可通过重点和表达直接程度提供选择，不为凑差异要求一条认错、一条反击。
- 离线评测只执行样例明确设置的禁用表达，不再套用全局普通词黑名单。旧黑名单常量仅保留给历史回归脚本重放，不参与线上评分。
- 现有独立评审、低于阈值/有明确缺陷时的一次修订、独立复评及人工采用逻辑保留。缺失评分仍不是低分，超时或无效结果不能当通过；没有增加无限重试。

## 5. 验收与尚未验证的部分

本轮在已有 conda `my_demo1` 中执行离线验证，未创建环境、安装依赖、调用付费模型或重传用户截图。

- 310 项后端测试通过，包含普通聊天直接输出、只加载选中正文、同模型工具回合、天气共存、调用预算、角色隔离、错误降级，以及多段文字在生成/重生成/评审/修订中保留。
- 四组前端脚本通过。真实 Chrome 在 1280px 和 390px 检查通过，覆盖多段展开、高风险等待解除、编辑保护、光标保持、修订稿主动采用、超时与局部评估失败。
- `scripts/compare_reply_policy.py` 的六条离线探针通过格式/评分来源检查。完整多段说明旧本地规则为 3/5，短但漏题的认错句旧规则为 5/5；新规则两者都不猜质量分，由独立评审结合上下文判断。

可在项目目录复跑：

```bash
conda activate my_demo1
python -B scripts/run_tests.py
python -B scripts/compare_reply_policy.py
```

开发案例保存在 `chat_reply_agent/evals/reply_policy_cases.yaml`，涵盖通话冲突、同事交付、家人安排、普通闲聊和有依据的道歉。包含应保留的信息、应避免的错误和可选策略，供人工对照；它不是通用评测页面的数据格式，也不会被线上模型自动读取。

这些是规则和程序行为验证，不能证明真实模型一定会选择正确策略或回复质量已经提高。下一步需在固定模型、固定输入和记忆的条件下，分别开启/关闭策略工具测试，多次记录首轮与总耗时、调用次数、完整性、事实准确性、双方情绪照顾和人工偏好。通话案例已用于开发，不能当独立盲测成绩。

生效方式：重启原 FastAPI 服务并刷新页面；选择“按内容决定”或“稍完整”。本轮没有替换正在运行的服务，也没有自动发送聊天消息。
