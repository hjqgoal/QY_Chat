# OCR 与评估协议修复验收

项目路径：`/Users/jiaqihong/Desktop/QY_Chat`。环境：conda `my_demo1`。
这是同日恢复/超时补丁之后的记录，不是一次新版本发布或生产级保证。
本轮没有修改真实 `.env`、主模型、数据库结构、个人记忆或依赖。

## 定位到的问题

- 评估截图中的 `original_text_mismatch` 是回抄原文与输入不一致，不等于 JSON 语法错误。旧只读协议重复输出 `reply.text`、`review.evaluated_text`、整组 `evaluated_texts`；任一条失败会使整批评价作废。没有保留该次原始响应，不能断言具体是标点变化还是改写。
- OCR 旧提示同时要求气泡位置、文字、时间、两项置信度和备注。合成实测中，简化后的 OCR 返回了完整 32 条消息，但使用顶层 JSON 数组；旧解析器只接受 `messages` 对象，因而误触发备用模型。不能据此推断用户所有历史失败都是同一原因。
- 官方说明 `qwen3.5-ocr` 不支持结构化输出约束，但支持用户提示提取文字。当前继续不向 OCR 发送 `response_format`。[模型说明](https://help.aliyun.com/zh/model-studio/qwen3-5-ocr)、[OCR 调用说明](https://help.aliyun.com/zh/model-studio/qwen-vl-ocr)。

## 本轮变化

1. OCR 仅要求逐气泡 `side`、`text`，不在这一步总结或分析情绪。兼容完整 JSON 对象及明确的消息对象数组，可有代码围栏；不接收普通散文、残缺 JSON 或没有位置字段的任意数组。重复消息保留，未知位置不猜。
2. OCR 简版不提取时间标签、不要求置信度。未提供置信度时沿用保守默认值与人工复核标记，备注说明缺失信息；默认值不是实测准确率。备用视觉模型仍用原完整提取格式。
3. 保留已授权的最多一次备用识别，只在空内容、格式错误或输出截断时触发。没有把网络、认证、限流或过滤失败加入重试条件。
4. 只读评估使用每次请求独立的候选 ID 和组 ID。模型返回 ID、维度依据和问题，程序从本轮快照填入原文；模型不再回抄三份候选文本。独立改进版继续走修订与复评，不会覆盖原稿。
5. 按 ID 而非返回顺序绑定；旧请求、未知或重复 ID 不采用，重复 ID 的所有条目都失效。额外改写字段也不能被悄悄接受。编辑后的候选仍须重新评估，前端迟到结果保护不变。
6. 单条证据缺失不再清空其他有效评价。任务可以结束但质量报告为 `partial`，整体不通过、不计算整体分、不自动修订或重试。复评部分失败时保留原稿评价，不发布尚未完整验证的改进版。
7. 区分 `invalid_json`、`invalid_binding`、`incomplete_evidence` 和网络超时。前端显示具体原因，不再统一称为“格式校验未通过”。日志不记录模型原文、聊天或密钥。

只读协议位于 `services/quality_contract.py`，评估归一化位于 `quality_service.py`，后台终态处理位于 `quality_queue_service.py`。历史定向编辑调用仍使用旧编辑协议；线上后台评估、改进版复评和只读离线评测使用新协议。

## 验证结果

离线：**278 项后端测试通过**，四组前端检查通过，1280px / 390px 浏览器测试通过。
新增覆盖数组兼容、错误数据拒绝、引号/换行、顺序打乱、旧/错/重复 ID、缺失依据、部分结果保留、部分复评失败不发布、页面状态和转义。既有取消、超时、用户编辑、隐私与上传清理回归仍通过。

所有真实接口调用只使用脚本生成的合成数据；未重传用户原图。截图检查使用临时数据库、临时上传目录，退出时清理。质量接口检查不访问数据库。

| 测试 | 实测结果与边界 |
| --- | --- |
| 简版 OCR，标准交替发言长图 | 早期简版 5.19 秒；最终提示 3.69 秒。仅调用一次 `qwen3.5-ocr`，32/32 文字及说话人匹配，上传清理正常 |
| 简版 OCR，无头像、连续同侧发言与时间标签 | 最终保留提示 3.66 秒，仅调用 OCR；32/32 文字匹配，但第 1 条说话人错误。准确性检查退出非零，不能说全部正确；页面标为待校对 |
| 取消格式示例的提示实验 | OCR 返回无效结构，实际触发备用后总耗时 87.70 秒，32 条文字/角色匹配。该提示已弃用；此结果只记录恢复分支，不能算作最终提示直接 OCR 成功 |
| 只读评审，合成候选包含引号与换行 | 两次分别 56.65 / 54.23 秒，均 3/3 评价合法、绑定原文一致、校验错误为空。第二次是在清除 Skill 引用文件中的旧回抄指令之后运行 |

文字匹配忽略标点/空白；说话人逐条比较。以上是小样本单次耗时，不是 P95 或模型准确率统计。
两次评审包含“信息不足”，第一次还包含“建议调整”：协议有效不等于候选质量通过。新协议不能保证模型语义判断正确，也没有降低生成模型或关闭其推理。

**尚存限制：** OCR 仍可能漏行或错认说话人，特别是无头像的混合布局；必须人工校对。强模型评审仍约一分钟，有明确问题时的一次修订/复评还会增加耗时。本轮只真实验证了评估调用，修订完整链路依赖已有验收和本轮离线回归，不声称重新完成所有功能的真实接口验收。

## 使用

停止旧服务后重新启动，再刷新浏览器、重新识别/评估；已失败的旧任务不会自动重跑。

```bash
cd /Users/jiaqihong/Desktop/QY_Chat
conda activate my_demo1
python -m uvicorn chat_reply_agent.main:app --host 127.0.0.1 --port 8000
```

无需修改 `.env.example`，无需数据库迁移。重新验收可以运行 `python scripts/run_tests.py` 和四个前端测试。
需另行承担模型调用费用的合成检查：`python scripts/check_vision_flow.py --live --case long`、`--case mixed`、`python scripts/check_quality_model.py --live`。
`mixed` 用例保留已知说话人误判的准确性检查，不以 HTTP 200 代替通过。
