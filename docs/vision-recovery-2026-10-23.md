# 截图识别格式失败恢复

后续已增加 OCR 简版提取与对象/数组适配；最新验收和识别边界见 [OCR 与评估协议修复](ocr-quality-protocol-2026-10-23.md)。本文件保留较早的恢复/超时补丁记录。

## 后续超时修复

用户随后遇到 `APITimeoutError`。旧设置中，识图与一般文本请求共用 90 秒 SDK 网络超时；原合成长图恢复已耗时约 78 秒。没有该次服务日志，不能确认超时在首次 OCR 还是备用视觉模型，也不能排除网络或服务拥堵。

现在识图独立使用 `VISION_TIMEOUT_SECONDS=180`（实际 `.env` 和模板均已写入），文本仍使用原 `MODEL_TIMEOUT_SECONDS`，质量任务仍使用自身预算。只增加等待余量，不改变推理设置，不增加重试次数；网络超时仍立即结束当前识图流程，不再换模型重发。

错误提示区分“首次识别”和“自动重新识别”，显示当前模型和识图超时配置，不再把超时泛化成密钥/模型不存在。日志补充具体阶段、模型、安全错误类别及实测耗时；不打印图片、聊天或密钥。`/api/status` 可查看已加载的 `vision_timeout_seconds` 和 `vision_fallback_model`，用于确认是否已重启到新版。

180 秒是单次请求的 SDK 网络超时配置，不是承诺整次上传最多 180 秒；格式失败恢复、多张截图等情况会增加总时间，也不保证任何图片都成功。

超时补丁验收：265 项后端测试、四组前端检查通过。用同一张 32 条合成聊天图模拟首轮格式失败，再实际调用一次备用模型，88.60 秒返回 HTTP 200，32 条文字与说话人对照通过，临时文件清理正常。该次耗时仍低于旧 90 秒配置，不能据此证明已经解决用户原图的超时原因；真实原图没有重传。

检查时 8000 端口的现有服务还未返回新增的超时诊断字段，未自动重启用户进程。需停止旧服务，从本项目目录重启后再试。

## 变化

用户报告截图在校对前报“聊天结构无效”。原流程要求模型返回含 `messages` 列表的 JSON，格式不合格即终止；没有保留这次原始模型响应，所以不能断言究竟是普通 OCR 文字、缺字段还是 JSON 损坏。

现在每张图片最多调用两次：

1. 仍先调用 `OPENAI_VISION_MODEL_NAME`，本机保留 `qwen3.5-ocr`。
2. 仅空响应、无效聊天结构或 `finish_reason=length` 时，再从原图识别一次。使用独立配置的备用视觉模型，不把坏输出交给文本模型猜说话人，也不沿用被截断的半份聊天。
3. 备用模型使用相同服务地址及密钥。支持的模型使用结构化输出约束，OCR 不发送不支持的 `response_format` 参数。返回后仍由本地解析与角色归一化校验。
4. 恢复成功进入原有校对页面，每条标为待确认，备注显示恢复模型。失败则返回明确的 502，不继续生成、不存入记忆，临时上传文件始终清理。
5. 认证、权限、限流、网络超时、模型不存在或内容过滤不触发恢复。不会无限重试，也不会通过切换模型绕过拒绝。

用户已明确授权将同一截图在上述格式失败时发送给备用模型并承担额外费用。真实 `.env` 仅新增以下配置，没有改主 OCR、密钥、数据库或依赖：

```dotenv
OPENAI_VISION_MODEL_NAME=qwen3.5-ocr
OPENAI_VISION_FALLBACK_MODEL_NAME=qwen3.8-max
VISION_TIMEOUT_SECONDS=180
```

备用模型必须支持看图；留空则在同类失败时用原模型重试一次，不自动采用文本强模型。每次识图独立使用 `VISION_TIMEOUT_SECONDS`；若外层另有更小请求预算则不突破它。两次是各自的请求超时，不是总时限。批量上传逐张执行，每图最多两次，可能增加等待与费用。正常有效结果只调用一次。

日志只记录请求编号、尝试序号、模型、耗时和安全错误分类，不记录模型原文、聊天文本、图片路径或密钥。

## 验收

- 259 项后端离线测试通过。新增 12 项测试覆盖恢复次数、首轮成功不额外调用、过滤/认证等不重试、重复消息保留、角色归一化、校对标记、客户端关闭、日志隐私及单图/批量端点清理。
- 四组前端检查通过。1280px/390px 浏览器回归通过，新增恢复结果的警告、编辑/确认入口与转义检查；无横向溢出及页面脚本异常。
- 真实接口只发送脚本画出的 724 x 2172 合成聊天图，使用临时 SQLite 和临时上传目录，不读取本次用户图片或个人聊天记录。

| 真实测试 | 结果 |
| --- | --- |
| 正常 OCR 路径 | 6.13 秒，HTTP 200，校对页数据可用；只识别出预设 32 条中的 17 条，文字和角色整体对照不通过。没有自动触发备用，因为格式有效且未报告截断 |
| 首轮格式失败后的恢复 | 首轮错误由测试主动模拟，不发送首轮 API 请求；实际调用一次 `qwen3.8-max`，78.08 秒，HTTP 200；32 条全部提取，按忽略标点/空白的文字比较及逐条说话人比较均通过，结果标为待校对 |

**这验证了恢复路径可运行，不是对用户原图的重新识别验收，也不代表任意截图都不漏行。** 合法格式但内容错漏仍是当前 OCR 的局限；模型置信度不是实测准确率。不要把“自动恢复”宣传为自动质量保证。
