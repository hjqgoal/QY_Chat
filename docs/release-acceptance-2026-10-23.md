## 本次修复

真实组合测试中，天气模型最初遇到 `not_found` / `needs_clarification`。直接检查公开地名接口发现：查询“北京市”没有结果，而“北京”有结果，且包含其他省份的同名地点。

在 `services/weather_service.py` 中做了限定范围修复：

- 查询中文城市时去掉末尾“市”用于搜索。
- 仅在已明确 `CN` 且输入完整直辖市名时，保留该直辖市作为地区约束；没有省份的普通同名城市仍要求澄清。
- 保留调用者显式指定的地区，并额外校验返回的国家代码，不以默认城市代替。
- 新增 4 项回归，覆盖全称、普通城市歧义、国家/地区限制以及非中文地名。

修复后直接调用“北京市 / CN”成功；另一次真实强模型自动调用得到“北京 / 北京市 / CN / today / afternoon”，工具返回 `ok`，生成三条候选。两次验证分开记录，不将模型是否规范参数的随机性当作代码修复效果。

## 展示时必须说明

1. 这是本地辅助回复工具，不侵入微信，不自动发送消息。人工确认是正常流程，不是演示时掩盖错误。
2. 情绪/态度与质量评价是有证据约束的模型判断，不是读心或客观分数；改进版也可能不合格。
3. 已验证真实向量 RAG；SQLite 存文本，向量按请求计算，最近 60 条候选、默认最多 3 条召回。没有全量 ANN 索引或持久化向量缓存。
4. 质量队列在内存，重启丢失；记忆任务在 SQLite。单进程、无身份认证，user_id 是本地分组，不是安全登录身份；不要开放公网。
5. 外部模型和天气服务可能超时、限流或变更。当前生成可能几十秒，后台修订可能更久，不承诺稳定秒回。
6. 没有做压力测试、完整安全审计或大规模盲评，也没有对所有关系/全部评测样本付费跑一遍。离线回归与真实小样本验证不能替代这些工作。

## 建议演示顺序

1. 用独立演示数据库和合成身份，先展示文字背景入口。
2. 展示主题、时机、策略和三条候选；等待生成时讲解主流程。
3. 展示截图识别，逐条核对文字和说话人，再确认生成；识别异常则回文字入口，不假装识别成功。
4. 展示后台评估与用户编辑不被覆盖；有改进版时由用户显式采用。
5. 等待记忆任务完成，再展示同联系人语义召回、风格样本、反馈和删除。
6. 天气作为扩展示例：地点明确，核对日期/时段；失败时展示诚实的失败处理。
